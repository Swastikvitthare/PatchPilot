# Security Policy

## Supported versions

Security fixes are applied to the latest version on the default branch. No older release series are currently designated as supported.

## Reporting a vulnerability

Please do not publish exploitable details, credentials, proof-of-concept payloads, or sensitive user data in a public issue.

If GitHub private vulnerability reporting is enabled for this repository, use the repository's **Report a vulnerability** feature. Otherwise, contact the maintainer through the GitHub profile to arrange a private disclosure channel before sharing technical details.

Include, where possible:

- The affected commit or version.
- The affected component and configuration.
- A concise description of the security impact.
- Reproduction steps using a safe, non-production example.
- Any suggested mitigation.

Do not include real API keys, passwords, private source code, or personal data in a report.

## Scope and limitations

PatchPilot is a development-time static-analysis tool. Its findings can be incomplete or incorrect and must be reviewed by a qualified developer. It is not a substitute for a security audit, runtime testing, dependency scanning, or incident response.

Please allow maintainers reasonable time to investigate and coordinate a fix before public disclosure.
